# 品質改善計画

このドキュメントは、tact-downloader の安全性、信頼性、保守性を改善するための実施候補を優先順位順に整理したものです。

## 優先度1: データ破損とパス逸脱を防ぐ（完了）

### ダウンロードを原子的にする

対象: `tact_downloader/client.py`

通信切断やディスク障害による不完全なファイルの残存を防ぐため、最終保存先へ直接書き込まない方式へ変更しました。

対応:

- [x] 同じディレクトリの一時ファイルへ保存する
- [x] 転送完了後に `os.replace()` で最終ファイルへ移動する
- [x] 失敗時は一時ファイルを削除する
- [x] API にサイズ情報があれば保存サイズを検証する

### 保存先を vault 内に限定する

対象: `tact_downloader/downloader.py`

外部入力を含むパスを検証し、vault外への保存とサニタイズ後の名前衝突を拒否する方式へ変更しました。

対応:

- [x] 年度、学期、授業名をパスセグメントとしてサニタイズする
- [x] `DOWNLOAD_BASE` を vault からの相対パスに限定する
- [x] 最終パスを `resolve()` し、`VAULT_ROOT` 配下であることを検証する
- [x] `..` は無視せず不正入力として拒否する
- [x] リソースおよびサイトのサニタイズ後の名前衝突を検出する

### URL検証を強化する

対象: `tact_downloader/client.py`

URLのスキーム、正規化したホスト名、ポート、リダイレクト先を検証する方式へ変更しました。

対応:

- [x] `https` のみ許可する
- [x] 正規化したホスト名とポートを検証する
- [x] リダイレクト先も許可ドメインか確認する
- [x] API URLに埋め込むサイトIDをエンコードする

### 実装・実環境の検証結果

- [x] 優先度1の回帰テストを追加（8件成功）
- [x] 既存classifierテストを実行（97件成功）
- [x] TACTへのCookie再利用ログインを確認
- [x] 2026年度「認知科学演習」のリソース3件を実際に再取得
- [x] APIのサイズ情報と保存後のファイルサイズが3件すべて一致
- [x] 実ダウンロード後に一時ファイルが残っていないことを確認

## 優先度2: テストを信頼できる状態にする

現在のclassifierテストには、重要な回帰を見逃す問題があります。

- `tests/test_classifier.py:46` の `zip()` が件数差を無視する
- サイトID不一致を `continue` してしまう
- 保存先に使われる `course_name` を比較していない
- HTTP、ダウンロード、パス、CLI、認証、Obsidian連携が未試験

### 既存テストの完全比較

次の項目を比較する:

- 件数
- サイトID
- タイトル
- 年度
- 学期
- 授業名

スナップショット生成側も `course_name` など必要な項目を保存するように変更します。

パス処理:

- `../outside`
- 絶対パス
- 空の名前
- 禁止文字

ダウンロード:

- 通信途中の切断
- 一時ファイルの削除
- 原子的な置換

HTTPクライアント:

- タイムアウト

Obsidianスコープ:

- `大学/`
- 年度
- 学期
- 授業
- `TACTリソース/` 以下
- vault外のパス

### 品質ツール

最小構成として以下を導入する:

## 優先度3: ネットワーク障害を適切に扱う

対象: `tact_downloader/client.py:30`, `tact_downloader/auth.py:54`

HTTPタイムアウトがないため、ネットワーク障害時に処理が停止し続ける可能性があります。

対応:

- 接続タイムアウトと読み取りタイムアウトを設定する
- 429、502、503、504などGETの一時障害だけ限定的に再試行する
- 認証失敗、通信失敗、データ不正を別の例外として扱う
- 成功、スキップ、失敗を別々に集計する
- 失敗時は非ゼロの終了コードを返す

## 優先度4: Cookieと認証情報を保護する

対象: `tact_downloader/auth.py:122`

Cookieを通常のJSONファイルとして保存しています。

対応:

- Cookieファイルを所有者のみ読み書き可能にする
- 一時ファイル経由で原子的に保存する
- TACT認証に必要なCookieだけ保存する
- 壊れたJSONを明示的に処理する
- Cookieの保存場所、削除方法、機密性をREADMEに記載する
- `.env` のパスワードとTOTP secretの管理上の注意を記載する

## 優先度5: ダウンロード処理を共通化する

ダウンロード処理が次の2箇所に重複しています。

- `main.py:131`
- `tact_downloader/obsidian_cmd.py:70`

対象リソース取得、保存先計算、既存判定、dry-run、ダウンロード、結果集計を共通サービスへ集約します。CLI側は対象選択と表示を担当します。

## 優先度6: Obsidianセットアップを安全にする

対象: `scripts/setup-obsidian.py`

課題:

- `data.json` を全面置換し、既存設定を失う可能性がある
- プラグインをハッシュ検証なしで取得している
- ダウンロード途中のファイルが残る可能性がある
- Pythonパスとフォルダパスの引用が安全でない可能性がある
- JSON更新が原子的でない

対応:

- 対象コマンドだけIDで追加・更新する
- 既存設定を保持する
- 更新前にバックアップする
- 一時ファイルから原子的に置換する
- プラグインファイルのSHA-256を検証する
- 空白や引用符を含むパスをテストする

## 優先度7: 仕様とドキュメントを一致させる

修正対象:

- `--all` は「学期を検出できたサイトのみ」と明記する
- dry-runの副作用方針を明記し、可能なら副作用をなくす
- セットアップ手順に `venv/bin/playwright install chromium` を追加する
- 対応Pythonバージョンを明記する
- Obsidian連携のセットアップ方法を追加する
- Cookieと秘密情報の注意事項を追加する
- 学期検出が対応するタイトル形式を実装と一致させる
- `SITE_TITLE_PATTERNS` を正式に使うか、未使用設定として削除する

## 推奨する実施順序

1. classifierテストの比較漏れを修正する
2. パス安全性のテストと実装を追加する
3. ダウンロードを一時ファイル経由に変更する
4. HTTPタイムアウトを追加する
5. dry-runの副作用をなくす
6. 失敗件数と終了コードを追加する
7. pytest、Ruff、CIを導入する
8. Cookie保存を強化する
9. Obsidian連携の設定更新を安全にする
10. READMEと実装の仕様を一致させる
